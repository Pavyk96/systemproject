# Документация по System Project

## Назначение

`System Project` — это небольшая система управления проектами с двумя основными доменами:

- проекты
- задачи

Приложение использует:

- Spring Boot
- Spring Security
- Thymeleaf
- PostgreSQL

Интерфейс рендерится на сервере. Пользователь работает через HTML-страницы и формы, а не через отдельный SPA-фронтенд.

## Роли и модель доступа

### Администратор

Администратор может:

- просматривать всех пользователей
- просматривать все проекты
- создавать, редактировать и удалять проекты
- управлять участниками проектов
- просматривать все задачи
- создавать и редактировать задачи
- назначать задачи пользователям
- менять статус любой задачи

### Обычный пользователь

Обычный пользователь может:

- входить в систему
- открывать главную страницу
- видеть только те проекты, в которых он участвует
- видеть только те задачи, которые назначены ему
- менять статус только своих задач

Обычный пользователь не может:

- создавать или редактировать проекты
- управлять участниками проектов
- создавать или редактировать задачи
- удалять проекты

## Сценарий аутентификации

### Страница входа

- URL: `GET /login`
- Шаблон: `login.html`
- Доступ: анонимные пользователи
- Назначение: вход в систему

Отправка формы:

- URL: `POST /login`
- Поля:
  - `username`
  - `password`

Результат:

- успешный вход перенаправляет на `/`
- неверные учетные данные возвращают на `/login?error`

Сообщения на странице:

- `registered` после успешной регистрации
- `error` после неудачного входа
- `logout` после выхода из системы

### Страница регистрации

- URL: `GET /register`
- Шаблон: `register.html`
- Доступ: анонимные пользователи
- Назначение: создание учетной записи

Отправка формы:

- URL: `POST /register`
- DTO: `RegistrationRequest`
- Поля:
  - `username`
  - `password`

Валидация:

- `username`: обязателен, от 3 до 100 символов
- `password`: обязателен, от 6 до 100 символов

Бизнес-правила:

- имя пользователя должно быть уникальным

Результат:

- успех перенаправляет на `/login?registered`
- ошибка валидации или уникальности повторно рендерит форму

## Основные страницы

### Главная страница

- URL: `GET /`
- Шаблон: `home.html`
- Доступ: авторизованные пользователи
- Назначение: основная страница после входа

Что отображается:

- имя текущего пользователя
- сводка по проектам
- сводка по задачам
- сводка по пользователям только для администратора

Администратор видит:

- общее количество пользователей
- общее количество проектов
- общее количество задач
- список всех пользователей
- все доступные проекты и задачи, что для администратора означает все записи

Обычный пользователь видит:

- сводку по рабочему пространству
- только доступные ему проекты
- только задачи, назначенные ему

Навигация:

- ссылка на страницу проектов
- ссылка на страницу задач
- кнопка выхода

### Страница проектов

- URL: `GET /projects`
- Шаблон: `projects.html`
- Доступ: авторизованные пользователи
- Назначение: просмотр проектов

Режим администратора:

- видит все проекты
- может открыть форму создания проекта
- может открыть форму редактирования проекта
- может удалить проект
- может добавить пользователя в проект
- может удалить пользователя из проекта

Режим обычного пользователя:

- видит только проекты, в которых участвует
- имеет доступ только на чтение

Содержимое таблицы:

- название проекта
- описание проекта
- участники проекта

### Форма создания проекта

- URL: `GET /projects/new`
- Шаблон: `project-form.html`
- Доступ: только администратор
- Назначение: создание нового проекта

Отправка формы:

- URL: `POST /projects`
- DTO: `ProjectRequest`
- Поля:
  - `name`
  - `description`

Валидация:

- `name`: обязателен, от 3 до 150 символов
- `description`: обязателен, от 5 до 2000 символов

Результат:

- успех перенаправляет на `/projects`
- ошибка валидации возвращает ту же форму

### Форма редактирования проекта

- URL: `GET /projects/{id}/edit`
- Шаблон: `project-form.html`
- Доступ: только администратор
- Назначение: редактирование существующего проекта

Отправка формы:

- URL: `POST /projects/{id}`
- DTO: `ProjectRequest`

Результат:

- успех перенаправляет на `/projects`
- ошибка валидации возвращает ту же форму

### Управление участниками проекта

Добавление участника:

- URL: `POST /projects/{id}/members`
- Доступ: только администратор
- Параметр:
  - `userId`

Удаление участника:

- URL: `POST /projects/{projectId}/members/{userId}/remove`
- Доступ: только администратор

Удаление проекта:

- URL: `POST /projects/{id}/delete`
- Доступ: только администратор

## Страницы задач

### Страница задач

- URL: `GET /tasks`
- Шаблон: `tasks.html`
- Доступ: авторизованные пользователи
- Назначение: просмотр задач и изменение их статуса

Режим администратора:

- видит все задачи
- может открыть форму создания задачи
- может редактировать любую задачу
- может менять статус любой задачи

Режим обычного пользователя:

- видит только задачи, назначенные текущему пользователю
- может менять статус только этих видимых задач

Содержимое таблицы:

- название задачи
- описание
- проект
- исполнитель
- статус

Действия на странице:

- обновление статуса задачи
- ссылка на редактирование только для администратора

### Форма создания задачи

- URL: `GET /tasks/new`
- Шаблон: `task-form.html`
- Доступ: только администратор
- Назначение: создание новой задачи

Отправка формы:

- URL: `POST /tasks`
- DTO: `TaskRequest`
- Поля:
  - `name`
  - `description`
  - `projectId`
  - `assigneeId`

Валидация:

- `name`: обязателен, от 3 до 150 символов
- `description`: обязателен, от 5 до 2000 символов
- `projectId`: обязателен
- `assigneeId`: необязателен

Результат:

- успех перенаправляет на `/tasks`
- ошибка валидации или бизнес-логики возвращает ту же форму

### Форма редактирования задачи

- URL: `GET /tasks/{id}/edit`
- Шаблон: `task-form.html`
- Доступ: только администратор
- Назначение: редактирование существующей задачи

Отправка формы:

- URL: `POST /tasks/{id}`
- DTO: `TaskRequest`

Результат:

- успех перенаправляет на `/tasks`
- ошибка валидации или бизнес-логики возвращает ту же форму

### Обновление статуса задачи

- URL: `POST /tasks/{id}/status`
- Доступ:
  - администратор для любой задачи
  - обычный пользователь только для своих назначенных задач
- Параметр:
  - `status`

Доступные значения статуса:

- `NEW`
- `IN_PROGRESS`
- `DONE`

Результат:

- успех перенаправляет на `/tasks`
- недопустимое обновление вызывает ошибку доступа

## DTO-схемы

### RegistrationRequest

Используется в:

- `POST /register`

Поля:

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `username` | `String` | да | 3..100 символов, уникальное |
| `password` | `String` | да | 6..100 символов |

### ProjectRequest

Используется в:

- `POST /projects`
- `POST /projects/{id}`

Поля:

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `name` | `String` | да | 3..150 символов |
| `description` | `String` | да | 5..2000 символов |

### TaskRequest

Используется в:

- `POST /tasks`
- `POST /tasks/{id}`

Поля:

| Поле | Тип | Обязательное | Описание |
| --- | --- | --- | --- |
| `name` | `String` | да | 3..150 символов |
| `description` | `String` | да | 5..2000 символов |
| `projectId` | `Long` | да | id существующего проекта |
| `assigneeId` | `Long` | нет | id существующего пользователя или пустое значение |

## Запуск и инфраструктура

### База данных

Источник данных приложения настроен на PostgreSQL:

- хост в конфигурации приложения: `project-postgres`
- порт: `5432`
- база данных: `naumen`
- пользователь: `project`
- пароль: `project`

Для локального Docker Compose:

- имя сервиса PostgreSQL: `postgres`
- имя контейнера: `project-postgres`
- образ бекенда: `payk96/systemproject:latest`

### Начальный администратор

При запуске приложение создает учетную запись администратора, если ее еще нет.

Свойства:

- `app.bootstrap-admin.username`
- `app.bootstrap-admin.password`

Текущие значения по умолчанию в конфигурации:

- username: `admin`
- password: `admin`

## Swagger и сгенерированная техническая документация

Swagger документирует маршруты контроллеров, payload форм и DTO-схемы.

Доступные endpoints:

- UI: `http://localhost:8080/swagger-ui/index.html`
- JSON: `http://localhost:8080/v3/api-docs`
- YAML: `http://localhost:8080/v3/api-docs.yaml`

Примеры экспорта:

```bash
curl http://localhost:8080/v3/api-docs -o openapi.json
curl http://localhost:8080/v3/api-docs.yaml -o openapi.yaml
```

## Типовые пользовательские сценарии

### Сценарий 1: первый запуск

1. Запустить PostgreSQL.
2. Запустить Spring Boot приложение.
3. Открыть `/login`.
4. Войти под учетными данными начального администратора.

### Сценарий 2: администратор создает рабочие данные

1. Открыть `/projects/new` и создать проект.
2. Открыть `/projects` и добавить участников в проект.
3. Открыть `/tasks/new` и создать задачу, связанную с этим проектом.
4. При необходимости назначить задачу пользователю.

### Сценарий 3: обычный пользователь работает со своими задачами

1. Зарегистрировать нового пользователя или использовать существующего.
2. Администратор добавляет пользователя в проект и назначает ему задачу.
3. Пользователь открывает `/tasks`.
4. Пользователь меняет статус задачи через форму на странице.

## Архитектурное замечание

Swagger здесь полезен как техническая документация, но проект не является чистым REST API. Основная модель взаимодействия — HTML-страницы и отправка форм. Поэтому `docs/pages.md` нужно считать основной функциональной документацией, а Swagger — сгенерированной справкой по маршрутам и схемам.
